# Avatar Prompt System

Build every card-avatar prompt from three layers:

1. Read `COMMON.md` for the visual system shared by every card.
2. Read exactly one planning-level file: `MACRO.md`, `MEZZO.md`, `MICRO.md`, or `SESSION.md`.
3. Create a card-specific brief from `CARD_BRIEF_TEMPLATE.md`.

Planning level is a visual class, not a parent-child relationship. Each card has one stable avatar. Card relationships remain in the app and do not determine avatar anatomy, species, or inheritance.

Do not add extra style directions when assembling a prompt. The shared contract plus one level contract plus one card brief is the complete source of truth.

Before accepting a render, use `VISUAL_REVIEW.md` at the intended card size.
